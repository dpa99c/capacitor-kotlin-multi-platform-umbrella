# capacitor-kotlin-multi-platform-umbrella

The **umbrella approach** for Kotlin Multiplatform Capacitor plugins, built on
[`capacitor-kotlin-multi-platform`](https://github.com/dpa99c/capacitor-kotlin-multi-platform).

It has the same features as
[`capacitor-kotlin-multi-platform-consumer`](https://github.com/dpa99c/capacitor-kotlin-multi-platform-consumer) (device info,
plus accelerometer streaming with shared step counting and shake detection). Here, though, every feature
is a module of **one** KMP build. That build links into **one** iOS framework and **one** JS module, which
means one Kotlin runtime per app. The package registers **two Capacitor plugins**, `KmpDevice` and
`KmpMotion`.

|  | Consumer (multi-plugin) | **Umbrella (this package)** |
|---|---|---|
| Packages the app installs | `capacitor-kotlin-multi-platform` + `…-consumer` | `…-umbrella` only |
| Kotlin frameworks embedded on iOS | `CapacitorKmpCore` + `KmpConsumerShared` | `KmpUmbrella` |
| Size of those frameworks (arm64, stripped / compressed) | 5.9 MB / 1.8 MB | **3.2 MB / 0.95 MB** |
| Each additional feature on iOS | + ≈ 2.7 MB (one more runtime) | + its own code only (typically tens to hundreds of KB) |
| Kotlin/JS chunks on the Web | one per plugin | one |
| Features calling each other | only through JavaScript | direct Kotlin calls (`KmpMotion` uses the device feature) |

See [docs/EXTENDING.md › Alternative: one umbrella framework per app](https://github.com/dpa99c/capacitor-kotlin-multi-platform/docs/EXTENDING.md#alternative-one-umbrella-framework-per-app)
in the base plugin for when to choose which approach.

## How it is built

```text
kmp/
├── settings.gradle.kts         uses the base's build-logic, prebuilt `core` and version catalog (node_modules)
├── features/device/            KMP library: DeviceModule, DeviceInfoService, OsVersion, UserAgentParser + actuals
├── features/motion/            KMP library: MotionModule, MotionProcessor, SimulatedAccelerometer + actuals
│                               (depends on :features:device – a direct Kotlin dependency)
└── umbrella/                   links core + features into ONE XCFramework (KmpUmbrella) and ONE JS module
    ├── build.gradle.kts        iosFramework("KmpUmbrella") { export(device); export(motion) }
    └── src/jsMain/…/Bridges.kt @JsExport createKmpDeviceBridge() / createKmpMotionBridge()
android/…/KmpDevicePlugin.kt    @CapacitorPlugin("KmpDevice")  : KmpCapacitorPlugin – one class per file
android/…/KmpMotionPlugin.kt    @CapacitorPlugin("KmpMotion")  : KmpCapacitorPlugin
ios/Sources/KmpUmbrellaPlugin/  KmpDevicePlugin.swift, KmpMotionPlugin.swift (+ Generated/KmpCapacitor.swift)
src/                            definitions.ts (both APIs), web.ts (both web classes → same Kotlin/JS module)
example/                        Vite + Capacitor demo app (Android, iOS, Web)
```

**The base plugin is a build-time dependency only** (`devDependency`). The umbrella uses its convention
plugin, prebuilt `core` and versions. `npm run kmp:build` then runs `scripts/sync-from-base.mjs`, which
copies the pieces the published package needs:

- the `core` Maven artifacts, into this package's `kmp-repo/`
- the Swift helper `KmpCapacitor.swift`, into `ios/Sources/KmpUmbrellaPlugin/Generated/`
- the TypeScript helper `KmpWebPlugin`, into `src/generated/`

The published package is therefore self-contained. **Apps must not install `capacitor-kotlin-multi-platform`
next to the umbrella.** If they did, Capacitor would link the base's own `CapacitorKmpCore` framework,
which is a second Kotlin runtime.

## Install

```bash
npm install capacitor-kotlin-multi-platform-umbrella
npx cap sync
```

## Usage

```ts
import { KmpDevice, KmpMotion } from 'capacitor-kotlin-multi-platform-umbrella';

const info = await KmpDevice.getDeviceInfo();
console.log(info.summary); // "Google Pixel 9 Pro · Android 16.0 · en-GB"

// The motion feature asks the device feature (inside the same Kotlin runtime) whether this is an
// emulator/simulator and recommends a source.
const { recommendedSource } = await KmpMotion.isMotionAvailable();

await KmpMotion.addListener('step', ({ count, cadence }) => console.log(count, cadence));
await KmpMotion.addListener('shake', ({ intensity }) => console.log('shake!', intensity));
await KmpMotion.addListener('motion', (s) => console.log(s.x, s.y, s.z, s.pitch, s.roll));
await KmpMotion.startMotionUpdates({ source: recommendedSource, intervalMs: 50 });
// …
const summary = await KmpMotion.stopMotionUpdates(); // { samples, steps, shakes, running }
```

API reference (generated by docgen): [docs/KmpDevice.md](docs/KmpDevice.md), [docs/KmpMotion.md](docs/KmpMotion.md).

On the Web, call `requestMotionPermission()` from a click handler first (iOS Safari requires it). The
iOS Simulator and desktop browsers have no accelerometer, so use `source: 'simulated'` there.

## Adding a feature

1. Create `kmp/features/<name>/build.gradle.kts` with `id("io.github.capacitorkmp.plugin")` and
   `capacitorKmp { android(namespace = …) }`. Leave out `iosFramework`: only the umbrella declares one.
2. Write a `KmpModule`, with a no-arg constructor for Swift, plus `expect`/`actual`s and `commonTest`
   tests.
3. In `kmp/settings.gradle.kts`, add `include(":features:<name>")`.
4. In `kmp/umbrella/build.gradle.kts`, add `api(project(":features:<name>"))` and `export(project(":features:<name>"))`.
5. In `kmp/umbrella/src/jsMain/…/Bridges.kt`, add `@JsExport fun create<Name>Bridge()`.
6. Add the plugin glue, **each class in its own file**:
   - an Android `@CapacitorPlugin` class extending `KmpCapacitorPlugin`
   - an iOS `CAPPlugin`/`CAPBridgedPlugin` class
   - in TypeScript, an interface in `definitions.ts`, a web class in `web.ts`, and a memoised
     `registerPlugin` in `index.ts`
7. Run `npm run build`, then `npx cap sync` in the app.

The Capacitor CLI registers only the first plugin class it finds in each Kotlin/Swift file. On iOS its
regex also matches an `@objc(…)` written inside a comment, so never put that text in a comment above the
class.

## Example app

```bash
(cd ../capacitor-kotlin-multi-platform && npm install && npm run build)   # base (build-time dependency)
npm install && npm run build                                             # this plugin

cd example
npm install
npm run build && npx cap sync
npx cap run android      # or: npx cap run ios  |  npm start (web)
```

## Development

```bash
npm run kmp:test   # 20 shared tests on JVM (Android host), iOS simulator and Node
npm run build      # kmp:build (Gradle capacitorExport + sync-from-base) + TypeScript/rollup + docgen
npm run verify     # xcodebuild + Gradle build/test + web build
npm run lint
```
